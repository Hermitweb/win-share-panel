# WinShare Panel 界面评审报告（资深 UI/UX + 前端设计评审）

- 评审对象：WPF 版 WinShare Panel（`net/WinShare.App`，v2.2.0）
- 取证方式：实机运行 + UI Automation 驱动截图（1600×1000 / 1024×900），暗色与浅色两套主题，覆盖主界面 6 个页面、新建共享向导、新建本地用户对话框、命令面板、「更多」下拉菜单
- 评审基线：界面应靠图标、布局、层级、交互自解释；**界面 ≠ 说明书**，可见文案只保留动作、风险、合规、歧义消除、无障碍所需
- 证据文件：`.repro/ui-shots/rev/`（`p1`–`p6` 主界面、`d*`/`e*`/`f*`/`h*`/`j*` 弹窗与菜单、`i1` 1024 断点、`crop-*` 局部放大）

---

## 0. 结论摘要

整体骨架健康：侧栏导航 + 卡片栅格 + 表格 + Toast/MessageStrip 的层级清晰，深浅主题一致，字号令牌（11/12/13/14/16）已收敛，行高与圆角语言统一。

但**本轮仍有 4 个 P0 级可用性缺陷**（不是审美问题，是功能不可达/视觉破损）：

| # | 缺陷 | 影响 |
|---|---|---|
| P0-1 | 共享表「操作」列最后一个动作「删除」被卡片右边界裁掉 | 破坏性操作不可达 |
| P0-2 | 共享/用户页搜索框的占位提示被输入框背景完全遮住 | 唯一的搜索入口没有 affordance |
| P0-3 | 仪表板趋势图图例色块直接压在「连接数/打开文件」文字上 | 图例不可读 |
| P0-4 | 「新建本地用户」对话框「分配到组」的控件被裁切，与「创建/取消」按钮重叠 | 分组功能不可用 |

另有 1 个 P0 级结构问题：**表头重名**（「端口」×2、「认证」×2）与**冗余小字残留**（向导账号墙、命令面板逐行副标题、趋势卡副标题等）。

修复顺序建议：P0-1 ~ P0-4 → 表头重名/断点裁字 → 冗余小字专项 → 全尺寸适配。

## 1. 框架与导航（主界面）

### F1（P0）共享表「操作」列末项被裁切
1. **问题**：`Views/Shares/SharesPageView.xaml` 操作列 `Width="200"`，内含「详情/禁用/编辑/权限/删除」五个文字动作，但列宽不足 + 卡片右边界裁切。1600px 宽下「删除」只剩「删」且右半被切（`rev/j1-light-dashboard.png`、`rev/e1-wizard.png`）；1024px 断点下「删除」整项消失（`rev/i1-tablet-1024.png`）。
2. **影响**：删除是破坏性操作，却是最容易丢失、最难恢复的一项；用户以为没有删除功能，或点到半个字。窄屏下功能直接消失。
3. **建议**：
   - 操作列改「图标 + ToolTip」并把次要动作收进 `⋯` 溢出菜单（详情/编辑/权限 为一级，禁用/删除 进菜单，删除置顶且用 danger 色）；
   - 若坚持文字动作：列宽改为 `Width="Auto"` + `MinWidth="200"`，并把「删除」移出该列、改为行内最后一枚 danger 图标按钮（固定 28×28 命中区）；
   - 断点 ≥1280 全展开、1100–1279 收进 `⋯`、<1100 只保留 `⋯`。
4. **优先级**：**P0**

### F2（P0）搜索框占位提示不可见
1. **问题**：`SharesPageView.xaml:80-86` 与 `UsersPageView.xaml:80-86` 把提示 `TextBlock`（`SearchHint`）声明在 `TextBox` **之前**，而 `InputBoxSoft` 背景不透明 → 提示被完全覆盖。运行时 `SearchHint.Visibility=Visible`（`SharesPageView.xaml.cs:301`）但屏幕上什么都没有（`rev/crop-search.png` 放大后确认为纯空白输入框；暗色 `rev/h4-drawer.png`、浅色 `rev/j1-light-dashboard.png` 同样复现）。
2. **影响**：用户无法判断这个框是搜索框、填什么、过滤哪些字段——这是共享页与用户页唯一的检索入口。
3. **建议**：改用 `TextBox` 的 `TextBoxStyle` 模板内建 watermark（Adorner 层，`PART_` 之上绘制），或把 `SearchHint` 移到 `TextBox` **之后**并设 `IsHitTestVisible=False`；同时统一 placeholder 文案为「搜索名称、路径、描述…」「搜索用户名…」。
4. **优先级**：**P0**

### F3（P1）表头重名造成歧义
1. **问题**：共享表同时出现两列「端口」（`FtpPortText` / `WebdavPortText`）与两列「认证」（`FtpAuthText` / `NfsAuthText`），在「全部」协议视图下同屏并列（`rev/j1-light-dashboard.png` 表头可见）。
2. **影响**：用户无法判断某列属于哪种协议；这是协议专属字段被强行拉平到通用表的结果，属结构问题而非文案问题。
3. **建议**：按协议分组或按所选协议动态显隐列——选中 SMB 时只显示 SMB 相关列；或在表头加协议前缀（`FTP 端口`/`WebDAV 端口`/`FTP 认证`/`NFS 认证`）并把协议专属列在「全部」视图下默认隐藏。
4. **优先级**：**P1**

### F4（P1）1024 断点：协议标签文字被裁
1. **问题**：断点下「协议」列收窄，胶囊标签里 "SMB" 只剩 "SM"（`rev/crop-tag.png` 放大确认，末字母被裁）。
2. **影响**：标签语义失真，"SM" 无法辨认协议。
3. **建议**：标签改为 `Auto` 宽度 + `MinWidth`、内边距自适应（`Padding="10,1"` 在 13px 字号下对 3 字母不足）；或断点下协议列用纯色块 + ToolTip（去掉文字，靠颜色 + 悬浮识别），但需保证色块有形状差异（形状编码优于仅颜色）。
4. **优先级**：**P1**

### F5（P1）1024 断点隐藏了「名称」列
1. **问题**：断点隐藏了「描述/作者/端口」，但 `名称`（主识别字段）在该断点仍显示，而 `i1` 截图里「名称」列内容（IPC$）实际未出现在可见区（只见协议标签与 SSL/认证等派生列）——识别路径被派生列挤占。
2. **影响**：用户无法确认自己在操作哪一行。
3. **建议**：断点优先级固定为「名称 > 协议 > 状态 > 操作」，其余按需隐藏；名称列 `Width="*"` 且**永不隐藏**（可隐藏的只有描述/作者/加密/连接数/NFS 权限等派生列）。
4. **优先级**：**P1**

### F6（P1）断点下表头截断（"NFS权限"→"NFS权"）
1. **问题**：`NFS权限` 列 `Width="70"`，断点收缩后表头被裁（`rev/i1-tablet-1024.png`）。
2. **影响**：表头语义不完整，且表头与内容不同宽造成对齐错觉。
3. **建议**：表头统一使用短词（`NFS 权限`→`权限`）、列宽按内容自适应 `Width="Auto"` + `MaxWidth`，并给表头行加 `TextTrimming=CharacterEllipsis`（裁切时给 Tooltip）。
4. **优先级**：**P1**

### F7（P1）<1100 侧栏退化为纯图标，缺当前页文字指示
1. **问题**：`MainWindow.xaml.cs` 宽 <1100 时 `NavRail.Width=72` 并隐藏标题文字；侧栏只剩 6 个图标（含底部 ⚡），当前页仅靠背景色块区分（`rev/i1-tablet-1024.png`）。
2. **影响**：新图标语义不可自解释；当前页在高 DPI/小屏下辨识度下降；无障碍缺可读名称（若有 ToolTip 则尚可，需确认已提供）。
3. **建议**：图标化状态下每个项必须带 `ToolTip`（= 页面名）+ 选中项左侧 3px 主题色指示条（颜色 + 形状双重编码）；悬停时以浮层展开文字标签（mini flyout），而不是只有 ToolTip 文字。
4. **优先级**：**P1**

### F8（P1）「更多」菜单的主题项没有选中态
1. **问题**：`MainWindow.xaml:63-64` 的「浅色主题/深色主题」是两个普通 `MenuItem`，无 radio/checkmark；用户无法判断当前主题（`rev/j0-more-light.png`、`rev/e1-wizard.png` 右上菜单）。
2. **影响**：状态反馈缺失；模式类设置应显式呈现当前值。
3. **建议**：改为 `MenuItem IsCheckable=True`，选中项打勾；同理「切换到新手模式」建议显示为「使用模式：新手/专家」两枚可勾选项，替代「切换到…」这种状态藏在动词里的写法。
4. **优先级**：**P1**

### F9（P2）窗口 `MinWidth=1000`，无更窄布局
1. **问题**：`MainWindow.xaml:6` `MinWidth="1000" MinHeight="660"`；实测把窗口拉到 640/420 宽会被系统钳制回 1000（`rev/i2`/`i3` 实测尺寸均为 1000×900/860）。
2. **影响**：平板竖屏（768 宽）、手机完全不可用；桌面小分屏也放不下。
3. **建议**：见第 6 节断点路线（P2 归入路线规划，但 MinWidth 下调需与表格改造同批做）。
4. **优先级**：**P2**（但属结构性）

## 2. 仪表板

### F10（P0）趋势图图例色块压住文字
1. **问题**：图例的色块被画在文字之上，「连接数」「打开文件」的首字被完全覆盖（`rev/crop-legend.png` 4× 放大确认）。
2. **影响**：图表最关键的读图信息不可读；且这种"重叠"在用户眼里像脏渲染。
3. **建议**：修 `Views/Charts/TrendChartControl.cs` 图例布局——色块矩形与文字基线同排、间距 ≥6px，色块 8×8 圆角矩形；不要用绝对坐标覆盖文本，改用水平 StackPanel 计算尺寸。
4. **优先级**：**P0**

### F11（P1）趋势卡副标题属说明书式小字
1. **问题**：卡标题「连接数 24h 趋势」右侧常驻灰色副标题「每 5 分钟采样 · 最多 288 点」（`rev/p1-dashboard.png`）。
2. **影响**：把采样细节提到标题层级，挤占视觉重心，属于典型"注释堆"。
3. **建议**：删除副标题，改为标题/图表的 `ToolTip`；采样间隔若要可见，应做成图表右上角一枚 12px 的 chip（如 `5min`），悬停显示完整说明。
4. **优先级**：**P1**

### F12（P1）协议分布卡右侧大片空白
1. **问题**：协议分布用两个 240px 定宽纵列拼装（`DashboardPageView.xaml.cs:188-190`），在 1300px 宽的卡内只占左半，右侧约 45% 完全空白（`rev/p1-dashboard.png`）。
2. **影响**：视觉失衡；协议是本卡唯一信息，浪费了最强的一屏区域。
3. **建议**：改为按卡宽自适应的 4 列（或 `WrapPanel` + `MinWidth=200` 自换行），每项用「色块标签 + 共享数 + 会话数」横向排布；4 个协议刚好一行 4 列，超宽时再折行。
4. **优先级**：**P1**

### F13（P2）图表 Y 轴刻度重复（1, 1, 0, 0）
1. **问题**：趋势图左轴出现「1 1 0 0」四个刻度值（`rev/p1-dashboard.png`）。
2. **影响**：刻度失去刻度意义（重复值），用户无法读出量级。
3. **建议**：刻度去重（相同值只保留首末），或按 `Max/2` 生成等距刻度；值全为 0 时只显示一个 `0`。
4. **优先级**：**P2**

### F14（P2）统计卡的点击 affordance 不一致
1. **问题**：前三张统计卡可点击跳转（已实现），第四张「服务状态」是状态标签而非数字，两类卡片同排但形态不同（`rev/p1-dashboard.png`）。
2. **影响**：同排卡片的心智模型不齐。
3. **建议**：要么四张全部可点击（服务状态跳转设置页），要么状态卡独立成组（放在右侧色块区），不要与数量卡混排。
4. **优先级**：**P2**

### F15（P2）「需要关注」空态的重心分散
1. **问题**：卡内「暂无需要关注项」居中，下方左角还有「已跳过：SMB 配置探测、磁盘水位读取」（`rev/p1-dashboard.png`）。
2. **影响**：空态时这两行一居中一角落，读起来像两件事。
3. **建议**：跳过项收进标题行右侧的 `chip`（`已跳过 2 项`，点击展开明细），空态区只保留一句状态。
4. **优先级**：**P2**

## 3. 共享管理页

### F16（P1）加载态超过 14 秒且无骨架/进度/取消
1. **问题**：进入共享页后，表体持续显示「加载共享中…」（`rev/h4-drawer.png` 14 秒后仍在），期间表体完全空白、无骨架行、无分项进度、无取消入口（7 路并行 PowerShell 探测）。
2. **影响**：界面"像坏了"；用户无法判断是卡死还是慢，也无法改走手动路径。
3. **建议**：
   - 表体铺 6–8 行骨架行（低对比度占位块），首屏即刻有结构感；
   - 状态行改为「正在探测 SMB / NFS / FTP / WebDAV…（已完成 2/4）」的可数进度；
   - 超过 8 秒给「只加载 SMB」之类的降级按钮；
   - 加载超过阈值允许「先进入页面，后台继续刷新」。
4. **优先级**：**P1**

### F17（P1）标题下的常驻提示是说明书式小字
1. **问题**：「拖拽文件夹到本页可快速创建共享」常驻在标题下方（`rev/p2-shares.png`、`rev/h4-drawer.png`），而页面右上角已有「新建共享」按钮。
2. **影响**：两个入口说同一件事；提示句占标题区黄金位，且拖拽能力对多数用户不可用（需知道拖到哪儿）。
3. **建议**：删除常驻提示；把拖拽能力做成**交互反馈**——拖拽悬停到页面时整页出现虚线边框 + 居中浮层「松开以创建共享」（此时文案是必要的），以及空态里一句行动指引。
4. **优先级**：**P1**

### F18（P2）表头与单元格的对齐/节奏
1. **问题**：表头行高与内容行高不等、基线不齐；协议胶囊标签垂直居中而文字列顶对齐，同一行内出现两种基线（`rev/j1-light-dashboard.png`）。
2. **影响**：横向扫读时串行。
3. **建议**：统一行高（内容 40px / 表头 36px），所有单元格 `VerticalAlignment=Center`，标签胶囊与文字同基线。
4. **优先级**：**P2**

## 4. 用户权限页

### F19（P0）「新建本地用户」对话框底部控件被裁并与按钮重叠
1. **问题**：对话框「分配到组（可选）」标签下方应有的组选择控件不可见，按钮行「创建/取消」直接压在该区域（`rev/j3-newuser.png`）。
2. **影响**：分组功能不可用；按钮浮在内容上，看起来像"只能创建不能分组"。
3. **建议**：对话框内容改为 `ScrollViewer`（与新建共享向导同一策略，`MaxHeight` 随屏高计算），「创建/取消」固定在底部操作条；组选择控件保留可见。
4. **优先级**：**P0**

### F20（P1）对话框内复选框仍是系统默认样式
1. **问题**：新建用户对话框内「启用账号 / 允许用户修改密码 / 密码永不过期」为系统默认蓝色方框（`rev/j3-newuser.png`），与主界面 `CheckBoxSoft`（圆角、深色面、18px）的组件语言不一致。
2. **影响**：同应用两套控件观感，弹窗像另一个软件。
3. **建议**：所有弹窗统一引用 `CheckBoxSoft` / `RadioButtonSoft` / `InputBoxSoft`；建立"弹窗控件不得用系统默认样式"的规则并写进设计规范。
4. **优先级**：**P1**

### F21（P1）用户表列宽不均，右侧出现大空档
1. **问题**：列宽为「描述」过宽，「所属组 / 上次登录」被推到右侧，中间出现约 400px 空档（`rev/j2-users-light.png`、`rev/p3-users.png`）。
2. **影响**：表格在宽屏下"散架"，信息关系断裂。
3. **建议**：列宽改为「用户名 `*` / 全名 `160` / 状态 `80` / 描述 `*`(最大 320) / 所属组 `200` / 上次登录 `140` / 操作 `160`」，其中两列 `*` 均分剩余空间。
4. **优先级**：**P1**

### F22（P1）用户页没有空态与加载态
1. **问题**：表格区域在无数据/加载中时是一整块空白（`rev/p3-users.png`）。
2. **影响**：与共享页（有「加载共享中…」）不一致，页面像没加载出来。
3. **建议**：补与共享页同构的空态/加载态（骨架行 + 「正在读取本地用户…」/「没有符合条件的用户」+ 一键清空筛选）。
4. **优先级**：**P1**

### F23（P2）排序下拉与筛选开关并排，语义分组不清
1. **问题**：「仅用户名 ▾」「☐ 仅启用」「+ 新建用户」三个控件同排（`rev/p2`/`p3`），排序与过滤混在一行且无分隔。
2. **影响**：用户不确定下拉是排序还是过滤。
3. **建议**：下拉前加 12px 竖分隔线或明确标签（排序）；「新建用户」用主按钮样式，与左侧筛选区在视觉上分开（右侧对齐）。
4. **优先级**：**P2**

## 5. 会话监控页

### F24（P1）刷新区控件排布与语义不清
1. **问题**：右上角为「刷新间隔 [5s ▾] [暂停] [4s]」——「4s」是倒计时 chip 但无标签，紧贴「暂停」按钮，读起来像第三个动作按钮（`rev/p4-sessions.png`）。
2. **影响**：倒计时被误读为状态或按钮；"暂停"与倒计时的关系不明。
3. **建议**：倒计时改为带图标的小圆环/进度环（贴在「刷新间隔」下拉左侧），「暂停」改为图标按钮并带 ToolTip「暂停自动刷新」；下拉加前缀「每」。
4. **优先级**：**P1**

### F25（P2）空态位于超高卡片正中，四周留白过量
1. **问题**：单行表格 + 居中「暂无活动会话」撑满整屏高度（`rev/p4-sessions.png`）。
2. **影响**：页面显得空旷，且空态离用户视线起点远。
3. **建议**：表格区高度随内容（`Height=Auto`，最大 70%），空态置于表格上方第一屏内；或把「会话/打开文件」两枚统计 chip 与空态并排成引导卡。
4. **优先级**：**P2**

## 6. 服务配置 / 应用设置

### F26（P1）协议页「配置预设」下拉为空
1. **问题**：下拉未选中任何预设时显示为空白（`rev/v8-settings.png` 顶部「配置预设」下方），看起来像坏掉的控件。
2. **影响**：用户不知道这里可选什么。
3. **建议**：无选中时显示占位项「选择预设…」（灰色，SelectedIndex=-1），选中后再显示预设名 + 右侧「恢复默认」。
4. **优先级**：**P1**

### F27（P1）「高级参数（超时 / 协议版本 / 身份映射 / 网关）」标题是清单式小字
1. **问题**：折叠区标题用括号罗列内容（`ProtocolTabViews.cs` 各协议页签）。
2. **影响**：折叠标题本该是"一个概念"，括号清单让它变成说明书目录；且不同协议括号内容不同，破坏一致性。
3. **建议**：统一为「高级参数」；若需说明，放进展开区首行或 ToolTip。
4. **优先级**：**P1**

### F28（P2）「最近 200 条 / 最近 300 行」独立成行
1. **问题**：应用设置「日志与回收站」里这两个计数各占一行灰字（`rev/v12-logs-top.png`）。
2. **影响**：它们是计数元信息，不是内容，占一行正文位。
3. **建议**：并入卡标题行右侧（`操作回收站　200 条`），灰字 12px 右对齐。
4. **优先级**：**P2**

### F29（P2）协议表单区右侧留白
1. **问题**：协议表单用 150px 标签列 + 定宽控件，在宽卡内右侧留出大片空白（`rev/v8-settings.png`）。
2. **影响**：与「两列自适应」的原则不一致（仪表板已改 2×2 栅格，协议页未同步）。
3. **建议**：高级参数区的数值字段改 2 列栅格（`Grid` + `*`），与向导的访问控制 2×2 保持同一栅格语言。
4. **优先级**：**P2**

## 7. 弹窗与菜单

### F30（P1）「浏览」按钮看起来像字段标签
1. **问题**：向导里「浏览」按钮被放在「本地路径」输入框**上方**，与其它字段标签同一视觉层级（`rev/e1-wizard.png`）。
2. **影响**：用户会把它当成一个说明文字而非可点按钮。
3. **建议**：把「浏览…」做成输入框右侧的行内按钮（`DockPanel` 右停靠 + 12px 间距），或紧贴输入框右下角；文案用动词「浏览…」。
4. **优先级**：**P1**

### F31（P0/P1）「常用账号：Admin、Administrator、CodexSandboxOffline、…、Administrators（组）等」账号墙
1. **问题**：向导底部把本机全部账号以灰字长串铺开（`rev/crop-wizard-acl.png`）。
2. **影响**：最典型的说明书式 UI——信息全量暴露却无操作价值，占 3 行高度，把真正要填的 4 个下拉挤到视口外；还泄露本机账号名。
3. **建议**：完全删除这行。改为在四个权限下拉里提供可搜索的候选（现有下拉已能选账号），并在每格下拉右侧加一个 `+` 小按钮打开"选择账号"弹层；账号名只作为候选项出现，不做常驻清单。
4. **优先级**：**P0**（属"常驻冗余小字"里最严重的一处）

### F32（P1）「拒绝（NoAccess，显式拒绝项）」括号补充
1. **问题**：权限枚举标签带解释性括号（`rev/crop-wizard-acl.png`）。
2. **影响**：破坏四个枚举项的平行结构，且"显式拒绝项"是术语解释，普通用户看不懂。
3. **建议**：标签只留「拒绝（NoAccess）」，语义差异通过**顺序与颜色**表达（Deny 用 danger 色标 + 放在末位 + Tooltip「拒绝优先于其他权限」）。
4. **优先级**：**P1**

### F33（P1）访问控制四格的标签颜色与其它字段不一致
1. **问题**：「完全控制/更改/读取/拒绝（…）」四个标签为蓝色，与向导其它灰色字段标签不同（`rev/crop-wizard-acl.png`）。
2. **影响**：层级语言失守，蓝色被读作"可点击链接"。
3. **建议**：标签统一 `BrushFog`/`BrushTextSecondary`；如需强调，用分组标题（「访问控制」）+ 缩进/分隔线表达。
4. **优先级**：**P1**

### F34（P1）向导可重复叠加打开
1. **问题**：多次点击「新建共享」会开出多个同位置向导窗口（取证过程中叠出 3–4 个，Esc 与取消只能关掉最上层，`rev/e1`/`f1`/`g1` 连续可见）。
2. **影响**：用户以为界面卡住；多层窗口叠加后无法回到主窗口操作。
3. **建议**：打开前检查 `Application.Current.Windows` 是否已有该类型窗口，有则 `Activate()` 聚焦；或改为模态对话框 + 单实例。
4. **优先级**：**P1**

### F35（P2）向导内滚动条常驻 + 协议下拉英文枚举重复
1. **问题**：内容略超容器 → 滚动条常驻（视觉噪声）；协议下拉每一项都带英文（`SMB（Windows 文件共享）`/`FTP（…）`…），四个下拉重复同一模式。
2. **影响**：滚动条暗示"还有内容"，与"内容几乎都在"矛盾。
3. **建议**：滚动条改为 `Auto`（需要时才出现）；英文名只在首个协议项保留一次，或改为 Tooltip。
4. **优先级**：**P2**

### F36（P1）命令面板每行灰色副标题是说明书式
1. **问题**：每个结果行下有一行灰色说明（"概览共享与会话"/"创建/编辑/删除共享"/"管理本地用户与权限"/"SMB/NFS/FTP/WebDAV 配置与预设"…）（`rev/h1-palette.png`、`rev/crop-palette-row.png`）。
2. **影响**：命令面板的效率来自"扫标题→回车"，副标题逐行重复、拖慢扫视；这是把说明写成常驻文案的典型。
3. **建议**：删除全部副标题；改为「分组标题（导航 / 共享 / 用户 / 会话）」+ 每行一枚图标，用分组与图标承担语义。若确需区分动态实体，给动态行加右侧灰色 tag（如 `共享`）。
4. **优先级**：**P1**

### F37（P2）命令面板底部常驻键位说明
1. **问题**：「↑↓ 选择　Enter 执行　Esc 关闭」常驻底栏（`rev/h1-palette.png`）。
2. **影响**：与"自解释"目标冲突；多数用户不需要。
3. **建议**：仅首次打开显示一次（记住偏好后隐藏），或降为极低对比度 11px 灰字；也可只在结果为空时提示「输入以搜索」。
4. **优先级**：**P2**

### F38（P1）命令面板缺少分组与结果计数
1. **问题**：所有结果平铺，无分组标题，无「共 N 条」，无行图标（`rev/h1-palette.png`）。
2. **影响**：动态结果（共享/用户/会话）与静态导航混排，用户无法预期列表结构。
3. **建议**：加分组标题行（导航 / 共享 / 用户 / 会话），组内相对路径（`↑↓` 在组间跳转），底部显示「N 条」。
4. **优先级**：**P1**

## 8. 视觉与排版系统

### F39（P1）雾字行高偏紧
1. **问题**：`SettingsUi.FogText` 固定 `LineHeight=19` 配 12px 字号；长句被折行后行间几乎无呼吸（`rev/j1` 应用设置「导入会覆盖…」等）。
2. **影响**：密排小字读起来疲劳，正是"说明书段落"观感的来源之一。
3. **建议**：雾字 12px → 行高 20；正文 13px → 行高 21；卡片内多行说明最多 2 行，超出折叠进 Tooltip。
4. **优先级**：**P1**

### F40（P2）卡片内标题与内容的间距不统一
1. **问题**：同页不同卡片的"标题→首个控件"间距在 8/12/16 之间浮动（应用设置页最明显）。
2. **影响**：节奏不齐。
3. **建议**：统一用 `SettingsUi.Gap` 令牌（S=8 / M=12 / L=24），卡片头与内容一律 12，卡与卡之间 16/24。
4. **优先级**：**P2**

### F41（P2）输入框与下拉的边界/填充在两套主题下的对比
1. **问题**：浅色主题下搜索框呈浅蓝填充且与页面底色接近（`rev/j1`），暗色下靠描边区分（`rev/h4`）；两者识别强度不同。
2. **影响**：浅色主题下输入区边界弱（与 F2 占位不可见叠加，界面"没有输入框"）。
3. **建议**：**需实测**：以 3:1 非文本对比度核对输入框边界对页面底色；不足则加深描边或加 1px 内高光。标注为**待实测确认**。
4. **优先级**：**P2**（待实测）

## 11. 全尺寸界面适配建议

### 11.1 断点体系（以主窗口可用宽度为准）

| 断点 | 宽度 | 侧栏 | 表格 | 工具区 | 弹窗 |
|---|---|---|---|---|---|
| **XL 桌面宽** | ≥1440 | 216 全文字 | 全列显示；操作列图标+文字 | 顶部按钮全展开 | 单列表单居中 560–640 |
| **L 桌面** | 1200–1439 | 216 | 隐藏「作者 / WebDAV端口」 | 同上 | 同上 |
| **M 桌面窄 / 平板横** | 1100–1199 | 72 图标（hover 展开文字） | 隐藏「描述」；操作列收 `⋯` | 次要按钮移入 `⋯` | 同上 |
| **S 平板竖** | 900–1099 | 72 图标 | 只留「名称/协议/状态/操作」；其余进行详情抽屉 | 顶部按钮变图标 | 底部通栏操作条 |
| **XS 手机** | <900（当前不支持） | 汉堡抽屉 | 表格 → 卡片列表 | 底部标签栏 | 全屏页 |

> 现状：`MinWidth=1000` 使 S/XS 不可达；侧栏折叠阈值 1100，表格隐藏列阈值 1280/1024 存在**区间错位**（1024–1099 会同时命中"隐藏名称/路径/描述"与"未命中紧凑列宽"两套规则，F4/F5/F6 即由此产生）。建议统一为上表一套断点常量。

### 11.2 布局重组规则
1. **表格列优先级固定**：`名称 > 协议 > 状态 > 操作` 永不隐藏；其余列按 `操作列 → 状态列 → 派生列（认证/SSL/权限/端口/作者/加密/连接数）` 顺序隐藏。
2. **行操作降级链**：文字动作 → 图标+Tooltip → `⋯` 溢出菜单 → 卡片式底部操作条（XS）。
3. **协议专属列**：不靠"加前缀"解决，改成**按当前协议筛选动态显隐**（F3）。
4. **统计卡**：4 列 → 2×2（S）→ 横向滚动（XS）；卡片间距 16→12。
5. **协议分布**：由"两列定宽"改为自适应网格（F12）。

### 11.3 元素缩放规则
- **不缩放文字**：字号仅在 XL→L 时允许 13→12；其余断点字号不变，靠隐藏与重排适配。
- **触控目标**：≤1099 断点，所有可点元素命中区 ≥44×44（当前 CheckBox 视觉 18px / 命中 32px，触摸设备需补）。
- **图标**：MDL2 码位 12–16px 视觉、20–24px 命中；行内图标动作按钮 28×28（桌面）/44×44（触摸）。
- **圆角与阴影**：卡片圆角恒定 12/16，不随断点缩放；阴影层级不变。

### 11.4 文本折行规则
- 表头：`TextTrimming=CharacterEllipsis`，裁切时 Tooltip 显示全名；禁止表头被裁成半个词（F6）。
- 单元格：单行 + Ellipsis + Tooltip 全值；「描述」列允许 2 行（`TextWrapping=Wrap`, `MaxHeight=2行`）。
- 按钮文字：不折行，超长改图标 + Tooltip。
- 弹窗标题：不折行，超长截断 + Tooltip。
- 正文/说明：**禁止超过 2 行**；第 3 行起折叠进 Tooltip 或「更多信息」。

### 11.5 隐藏 / 折叠 / 优先级规则
1. **标题层**：标题 > 卡片头 > 分组标题 > 标签 > 正文；辅助信息一律降到 Tooltip。
2. **折叠区**：专家参数一律「高级参数」单标题；展开内容优先双列栅格。
3. **空态优先级**：一句状态 + 一个主按钮 + 可选一个次按钮，不超过两个动作。
4. **常驻与暂显**：拖拽提示、快捷键、采样细节、账号清单全部改为**触发时出现**（hover/拖入/聚焦）。
5. **状态 chip 化**：计数类元信息（200 条 / 5min / 已跳过 2 项）统一为标题行右侧 chip。

### 11.6 间距调整规则
- 页面边距：24（XL/L）→ 16（M/S）→ 12（XS）。
- 卡片内边距：16 → 12（S/XS）。
- 卡间距：24（XL）→ 16（L/M）→ 12（S/XS）。
- 表格行高：36 紧凑（桌面）→ 44（S/触摸）。
- 表单标签列：150 固定（M+）→ 标签置顶单列（S/XS）。
- 底部操作条：右侧按钮组（S/XS 改底部通栏，主按钮右侧）。
